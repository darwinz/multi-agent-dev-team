# Multi-Agent System v3.0 (PM → Coder ↔ QA over A2A) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a QA & Debugger agent and an iterative Coder ↔ QA loop to the v2 team.
- QA writes real pytest tests per task, runs them sandboxed, and returns structured fixes.
- The Coder self-critiques and revises once before QA, then revises from QA's fixes until the tests pass or `QA_MAX_ITERATIONS` (default 5) rounds are used.
- Every Coder ↔ QA exchange is an A2A message on a broker with intent validation, and it's logged.

Covers rubric C3.1–C3.6.

**Architecture:** The v2 outer graph gains `reflect_node` and `qa_node`, and `coder_node` becomes the Coder's A2A endpoint: deliver, revise, or close a task on QA's reply.
- `orchestration/a2a.py` holds the `Message` schema, a synchronous per-agent `Broker`, and `Endpoint`, which validates on receive.
- `orchestration/review.py` holds the models shared by QA, reflection and A2A payloads.
- `agents/qa_agent.py` generates a test suite once per task, writes it to the workspace, runs it with `exec_python` (new JUnit option), and converts the results into a `QAReport`.
- `TeamRunner` builds one broker per run and logs every A2A event to `a2a-log.jsonl` next to the v2 evidence files.

**Tech Stack:** Python 3.12, uv, LangGraph 1.2.x, langchain `with_structured_output`, Pydantic v2, pytest (JUnit XML), rich.

**Spec:** `docs/superpowers/specs/2026-11-02-qa-a2a-v3-design.md`. Read it in full before Task 1. Section numbers below (§5 etc.) refer to it.

## Review Focus

These five inputs are implied by the spec but not exercised by the main-path tests. Each gets a test in the task that owns the code.

1. **QA's generated suite imports a name the code doesn't define, or doesn't parse.** Expected:
   - an unparsable suite is retried once and then becomes a `qa_error`;
   - a parsable suite that fails at collection becomes a High issue carrying pytest's message, not a crash.

   Tests in Task 3 (`test_collection_error_is_issue`, `test_invalid_suite_retried_once`).
2. **Delivered code hangs under QA's test.** Expected: the process tree is killed at `exec_timeout_s`, there's one High "timed out" issue, the report isn't approved, and the loop continues. Test in Task 3 (`test_hanging_code_times_out`).
3. **The Coder edits or deletes `test_qa_<id>.py` (its own task's or an earlier task's) during a fix round.** Expected: QA restores every expected suite from its canonical copy before running and sets `tampered=True`. Tests in Task 3 (`test_suite_restored_when_tampered`, `test_prior_suite_restored_when_deleted`).
4. **The QA model errors on round 1.** Expected: `final_report(reason="qa_error")` right away, no Coder fix run, the task `failed`, the run `partial`. Test in Task 5 (`test_qa_error_ends_task`).
5. **`QA_MAX_ITERATIONS` is `0`, `6` or `abc`, via env or `--qa-max-iterations`.** Expected: `team` exits 2 with `team: invalid setting qa_max_iterations: …`. Test in Task 6 (`test_bad_qa_max_iterations_exits_2`).

  - **`coder_node`:**
    - When `qa_round == 0`: run the Coder on `render_task(h)` → `coder_step="deliver"`.
    - Otherwise: `msg = coder_ep.receive(task_id=h.task_id, correlation_id=state["outstanding_request"])`.
      - `approved` or `final_report` → close the task. Record `done`/`failed`, `qa_outcome` = `approved` / `unresolved` / `qa_error`, `unresolved` = issue lines. Advance the index, set `handoff=None`, `coder_step="close"`.
      - `fix_instruction` → run the Coder on `render_fix(h, FixInstruction(**msg.payload))`, then `coder_ep.send("qa", "review_request", ReviewRequest(task_id, round=qa_round+1, files=<disk hashes of task_files>))` → `outstanding_request`, `coder_step="revise"`.
    - Every Coder run merges `result.files` **over** `task_files` (`{**task_files, **result.files}`, never a replacement: `CoderResult.files` holds only that run's writes) and into `code_output`, adds to `artifacts`, and adds `result.iterations` to the record.
    - On `approved`, the node returns `approved_suites={task_id: state["qa_suite"]}`.
  - **`reflect_node`:** hash → `critique` → Coder run on `render_revision` → hash. Success needs a parsed critique **and** non-empty `changed`. On a `ReflectionError` or empty `changed`, retry the whole attempt once (the retry's revision text adds "Your previous revision changed no files; make the changes now."). Record one `Reflection` (with `error` set if both attempts failed) → round-1 `review_request` → emit `TeamEvent(kind="reflection")` → `reflected=True` only on success, plus state `reflection_ok: bool`.
  - **`qa_node`:** `req = qa_ep.receive(task_id=h.task_id)`; `report, suite = deps.qa.review(h, ReviewRequest(**req.payload), round=state["qa_round"] + 1, suite=state["qa_suite"], prior=state["approved_suites"])`. Reply on `req.correlation_id`:
    - `final_report(reason="no_revision")` if `not state["reflection_ok"]` (the report is still saved as diagnostic evidence);
    - `approved` if `report.approved`;
    - `final_report(reason="qa_error")` if `report.qa_error`;
    - `final_report(reason="max_iterations")` if `round == deps.qa_max_iterations`;
    - otherwise `fix_instruction`.

    Then emit `TeamEvent(kind="qa_report")` and return `qa_round`, `qa_suite`, `qa_reports`, and `qa_rounds`/`qa_test_file` on the record.
  - **`finalize`** (v2 plus the regression check, spec §4): if any task is `done`, `deps.qa.run_suites({id: approved_suites[id] for done ids}, task_id="regression", round=0)`. Each `done` task with a failing, erroring, skipped or missing test in its own suite becomes `failed`, `qa_outcome="regressed"`, with those issues in `unresolved`. Return `regression=<report dump>` and recompute run status.
  - `qa_node → coder_node` is a plain edge.
