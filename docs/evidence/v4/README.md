# Module 4 evidence map (C4.1 to C4.9)

Each row maps a rubric criterion to the code that implements it, the automated test that proves it, and the evidence you can open. Links are relative to this folder. The operating instructions are in the [README](../../../README.md#production-v4).

**Evidence kinds.**

- **Controlled runs** (`controlled/`): scripted models, no API keys, real subprocess execution and real resilience code. Regenerate with `uv run python -m scripts.resilience_runs`. They show behaviour on controlled failures; they are not live model runs.
- **Live runs** need real keys and spend money. They are **pending Task 18** and are marked so below. Nothing marked pending has been run.
- Default `pytest` is mocked and makes no paid calls.

## Notes for the assessor

- **What the controlled runs prove.** Retry, breaker, cache and the invalid-output path are exercised by the real production code with a scripted model. They are evidence of behaviour under failure, not of model quality. The invalid-*tool-call* probe is a test ([tests/test_security.py](../../../tests/test_security.py)), not a controlled run.
- **Counting calls.** In the cost report, `calls` counts successful model calls plus response-cache hits. A failed attempt that is retried produces no record; the record's `attempts` field shows how many tries the call needed.
- **Pricing** is from the Anthropic price tables as of 2026-11-08. Haiku's cache-read price is derived, and Haiku's above-100K-token tier is not modelled.
- **Reading the exit code.** See [Reading the outcome](../../../README.md#reading-the-outcome): 0 is a completed run whose demo check passed, 1 is `partial` (an unresolved-issue report per task) or `failed`, 2 is a configuration error, busy workspace or unreachable Chroma, 130 is an interrupt. The cost report's `outcome` matches.
