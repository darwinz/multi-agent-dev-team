# Module 4 evidence map (C4.1 to C4.9)

Each row maps a rubric criterion to the code that implements it, the automated test that proves it, and the evidence you can open. Links are relative to this folder. The operating instructions are in the [README](../../../README.md#production-v4).

**Evidence kinds.**

- **Controlled runs** (`controlled/`): scripted models, no API keys, real subprocess execution and real resilience code. Regenerate with `uv run python -m scripts.resilience_runs`. They show behaviour on controlled failures; they are not live model runs.
- **Live runs** (`live-bst/`, `docker-clean-start.log`, `make-verify.log`): real Anthropic models, real keys, real spend. See [Live runs](#live-runs) for what each one is and what it cost.
- Default `pytest` is mocked and makes no paid calls.

## Notes for the assessor

- **What the controlled runs prove.** Retry, breaker, cache and the invalid-output path are exercised by the real production code with a scripted model. They are evidence of behaviour under failure, not of model quality. The invalid-*tool-call* probe is a test ([tests/test_security.py](../../../tests/test_security.py)), not a controlled run.
- **"QA's suites exited 1" in the graded run's coverage line.** The demo check measures coverage by copying QA's suites into a temporary folder. Two of them (T3, T4) cover "tests pass with pytest" by running the Coder's `tests/test_bst.py`, which is not in that folder, so they fail there. Inside the run every QA round and the 63-test regression check passed. Coverage is reported, not gated, so the pass verdict does not depend on it.
- **Trace projects.** The graded trace is in the LangSmith project `default` (the BST runs had no `LANGSMITH_PROJECT` set); `.env.op` now sets `multi-agent-dev-team`. The Docker clean start ran without `LANGSMITH_TRACING`, so it has no trace; C4.1 is shown by the graded run.
- **Two cost figures.** LangSmith prices the graded run at $0.1486; the cost report says $0.1437. The report uses this project's own price table (see Pricing below).
- **Counting calls.** In the cost report, `calls` counts successful model calls plus response-cache hits. A failed attempt that is retried produces no record; the record's `attempts` field shows how many tries the call needed.
- **Pricing** is from the Anthropic price tables as of 2026-11-08. Haiku's cache-read price is derived, and Haiku's above-100K-token tier is not modelled.
- **Reading the exit code.** See [Reading the outcome](../../../README.md#reading-the-outcome): 0 is a completed run whose demo check passed, 1 is `partial` (an unresolved-issue report per task), `failed`, or a demo's check failed (the run is then `completed`, the report still says `success`; read `demo-check.txt`), 2 is a configuration error, busy workspace or unreachable Chroma, 130 is an interrupt. Otherwise the cost report's `outcome` matches the run status.
