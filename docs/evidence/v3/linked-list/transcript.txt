    bug linked_list.py: LinkedList.delete, `node.next = None`: Clearing the removed node's `next` silently truncates any live iteration. In `for v in ll: if pred(v): ll.delete(v)`, the generator resumes at the removed node, reads `node.next`, gets None and stops. The remaining items are skipped with no error. The class docstring says only that items may be skipped or repeated. Clearing `next` isn't needed for correctness, and it makes the common delete-while-iterating pattern worse than leaving the node alone.
    edge_case linked_list.py: LinkedList.delete, loop bound `range(self._size)`: If `_size` is stale and too small, for example from hand-edited nodes, delete misses a value that is really in the chain. It returns False even though `search` and iteration can still reach that node, with no signal that the invariant is broken. test_search_is_bounded_by_size_invariant covers this for search but nothing covers it for delete.
    edge_case test_linked_list.py: test_delete_on_cycle_terminates: This test only deletes a missing value, so it only checks that the walk ends. It never deletes an existing node in a cyclic list. Deleting the tail of `[1,2,3]` where `3.next` is head leaves `prev.next = head` and still decrements `_size`. Deleting the head leaves the tail pointing at the removed node. The behaviour on a cycle is untested and undocumented.
    edge_case linked_list.py: LinkedList.delete, `node.value == value`: Values whose `==` returns a non-bool, such as numpy arrays or pandas objects, make the `or` expression raise ValueError (ambiguous truth value) mid-walk. The error propagates and the list is left unchanged, which is acceptable. It is not tested, and the docstring doesn't mention this case.
    edge_case test_linked_list.py: delete tests, identity vs equality: No test checks that delete removes the first node with an equal value when a later node is the identical object.
